# AI Community Manager Assistant — Project Brief

> **Nota de arquitectura (v0.2, actual):** el proyecto evolucionó de una app CLI con LangGraph y
> API key a un **toolkit determinista agent-native**. OpenCode o Claude Code son el LLM y el
> orquestador; este repositorio aporta comandos, validaciones, parsing y persistencia. No hay
> llamadas a modelos ni secretos en el código. Ver `README.md` y `SPECS.md` para el estado actual.
> Las secciones de producto de este brief siguen siendo la referencia funcional.

## 1. Project Overview

**Goal:** Build a terminal-based AI assistant for content creators and community managers, inspired by the architecture of [`MadsLorentzen/ai-job-search`](https://github.com/MadsLorentzen/ai-job-search). The assistant must feel **functional, token-efficient, and intelligent**, acting as a structured agentic workflow rather than a free-form chatbot.

**Core value proposition:**
- Automates the heavy cognitive work of a CM (ideation, scripting, repurposing, analysis, drafting replies).
- Explicitly delegates to the human the tasks AI cannot do (video editing, publishing, sensitive replies) via a persistent `tasks.md` file.
- Produces clean, non-AI-sounding output by enforcing strict brand rules and a drafter-reviewer loop.

---

## 2. Core Philosophy

1. **Commands over chat.** The user interacts via explicit commands (`/setup`, `/script`, `/analyze`, `/tasks`), not free-form conversation. This keeps context tight and tokens low.
2. **State in files, not in chat history.** Brand rules, tasks, and scripts live in local Markdown files. Agents read them on demand instead of carrying 50 messages of context.
3. **Separation of concerns.** El agente host redacta y critica; el CLI determinista valida, persiste y crea tareas. Ningún componente hace todo.
4. **Respect the human's voice.** If the user provides a hook, it is used **verbatim**. The AI never "improves" creative decisions the user has already made.
5. **No filler.** Output is plain text. No `[epic music]`, no timelines, no visual directions. Editing is the human's job.

---

## 3. Tech Stack

| Layer | Choice | Rationale |
|---|---|---|
| Language | **Python 3.11+** | Ecosystem maturity and deterministic tooling |
| Host agent | **OpenCode / Claude Code** | The host model converses, drafts and orchestrates |
| Interface | **Slash commands + CLI** | Native to the host; fast and scriptable |
| Deterministic layer | **Python CLI (`python -m src`)** | Review, parsing, persistence and tasks without an LLM |
| State storage | **Local Markdown files** | Human-readable, editable, no external DB |
| Secrets | **None** | The project never stores or uses API keys |

## 6. Command Specifications

### `/setup`
- **Purpose:** Bootstrap or refresh `brand_context.md`.
- **Flow:**
  1. Ask 5 fixed questions: target audience, tone of voice, main goal, platforms, non-negotiables.
  2. Ask the user to paste 3–5 of their best past posts.
  3. El agente host extrae patrones (sentence length, emoji usage, recurring phrases, structure) y los cruza con las respuestas.
  4. Escribe `brand_context.md` con secciones: `# Identity & Audience`, `# Global Blacklist`, `# Voice & Tone Attributes`, `# Format Rules` y `# Style Examples`. Valida con `python -m src brand check`.
- **Output:** Confirmation message + path to the generated file.

### `/script "<topic>. Hook: <optional hook>"`
- **Purpose:** Generate a clean, publish-ready script.
- **Rules:**
  - If a hook is provided, it is inserted **verbatim** as the first line.
  - Output is plain text only. No visual/audio directions, no timestamps.
  - Structure: Hook → Body → CTA (if appropriate).
- **Drafter-Reviewer loop:**
  - Drafter receives: `brand_context.md` + user input.
  - Reviewer receives: the draft + `brand_context.md` (especially the Blacklist). Checks for AI-sounding phrases, missing CTA, tone mismatch.
  - If failed → Drafter retries with reviewer feedback appended (max 2 retries).
  - If passed → `python -m src save` writes `scripts/YYYY-MM-DD_<formato>_<slug>.md` and appends to `tasks.md`.

### `/analyze [week]`
- **Purpose:** Weekly performance review.
- **Input:** A CSV in `data/` (user downloads it manually from platform analytics — no API integration for now).
- **Output structure (strict template):**
  1. 🏆 **Winner** — top post + *why* (hypothesis grounded in data).
  2. 📉 **Loser** — worst post + what not to repeat.
  3. 🎯 **3 concrete adjustments** for next week (time, format, hook style, etc.).
- **Anti-pattern:** Never produce a generic "your content is great, keep going!" summary. Must be specific and actionable.

### `/tasks`
- **Purpose:** View and manage the human's to-do list.
- **Subcommands:**
  - `/tasks` → list all open tasks.
  - `/tasks done <id>` → mark complete.
  - `/tasks add "<description>"` → manual addition.

## 7. Business Rules & Constraints

### The "No AI Sound" Rule
`brand_context.md` must contain a **Blacklist** section. Default entries (user-editable):
- "unlock", "unleash", "dive into", "in the world of", "revolutionary", "game-changer"
- "desata", "revolucionario", "en el mundo de", "sumérgete" (Spanish equivalents)
- Excessive emoji clusters (🚀🔥💡)
- Overly formal connectors ("Furthermore", "In conclusion")

The Reviewer's **only** job is to flag blacklist violations and tone drift. It does not rewrite creatively.

### The "Respect the Human" Rule
- If the user's input contains a hook, opening line, or key phrase → preserve it **exactly**.
- Never expand a 1-sentence idea into a 5-paragraph essay unless asked.
- Never add visual/audio directions.

### The "Human-in-the-Loop" Rule
When the workflow detects a task the AI cannot perform, it **must** append to `tasks.md` in this format:

```markdown
- [ ] **EDIT** — Edit and publish script `scripts/2026-10-20_productivity.md`
  - Deadline: tomorrow 10:00
  - Notes: add dynamic subtitles, cut at 0:15
```

## 9. Token Efficiency Strategies

These are non-negotiable — they are what make the tool feel "fast and smart" like the reference repo.

1. **File-based state.** The host agent reads `brand_context.md` from disk per invocation. Never embed it permanently in chat history.
2. **Fresh deterministic review.** `python -m src review` audits the draft with a separate code path; the agent only receives the structured result.
3. **Structured reviewer output.** The CLI returns JSON:
```json
   {"passed": false, "blacklist_violations": ["unleash"], "retry_instruction": "..."}
```
   No prose. Saves context and makes retries trivial.
4. **Selective RAG (future).** When searching past posts for inspiration, retrieve only the top 3 most similar examples — never the whole archive.
5. **Verification checklist runs once.** The final checklist (review passed? file saved? task appended?) runs at the end of the flow, not at every step.
